Gemini 4 Hydrogen、Argon、Carbon 如何分工？从 RecalAI 与 Lunest 的工程决策看 Agent 成本

以 RecalAI 已有 BYOK、受控 Agent、本地证据引用，Lunest 音频中断恢复及 XBSTACK 双语发布验收为依据，讨论 Gemini 4 Hydrogen、Argon、Carbon 的分层路由、工具权限、任务成本、2026 年 API 价格变动和幂等恢复；未进行三模型真实 A/B。

Gemini 4 三模型怎么选？三个型号放在模型选择下拉框里，看起来只是“快、均衡、深度思考”的取舍；放到一个需要改源码、执行工具、恢复中断任务并承担实际隐私责任的 Agent 工作流里，问题就变成了：哪些操作值得多付费推理，哪些操作不应该交给模型，切换模型时怎样不丢状态，以及失败的调用由谁买单？

2026 年 11 月 12 日，Google 发布 Gemini 4 Hydrogen，定位更快的日常编码和 Agent 执行。Google 将 Argon 视为广泛软件工程与知识工作中的主要选择，将 Carbon 放在更复杂的多阶段和长时任务上。Google Antigravity 的 Orchestrator 还展示了在一次开发会话中动态分配 Hydrogen 和 Carbon 的路线。这是厂商公开的定位与产品结果，不是 XBSTACK 项目的任务成绩。Google Hydrogen 官方公告 · Carbon 公告

本文不讲如何填写 API Key 或调用 generateContent。我们以三个具有实际工程验收边界的场景分析模型路由：RecalAI 的精确引用与本地资料处理、Lunest 的整夜音频异常恢复、XBSTACK 中英文文章与网站部署质检。这些是可设计、可复核的真实项目任务，不意味着三个 Gemini 模型已经被接入应用或完成收费 API A/B 测试。

先区分两笔账：Gemini 推理与云语音不是同一项服务

本篇比较的是收费或限额免费云端大模型在 Agent 工程里的任务分工。这不是“Google AI Edge 的付费语音版”。如果 RecalAI 需要将用户说话转成文字，优先判断设备本地 ASR 是否可用；只有用户明确选择云识别，才另外评估 Google Cloud Speech-to-Text 等按音频处理量计费的服务。需要合成语音时另行评估 Google Cloud Text-to-Speech 等按声音 SKU、字符或生成式 Token 计费的产品；Hydrogen、Argon、Carbon 的文本推理 Token 价格不能当作上述语音费用。

同一条 RecalAI 任务可以“本地 ASR → 本地检索 → 用户授权的 Gemini 推理 → 本地 TTS”，也可以全程本地。每个箭头都涉及独立的离线资格、数据出站选择和回退规则。Lunest 则更偏向端侧确定性控制，付费 Gemini 更适合辅助开发阶段的复杂调试，不是夜间整夜音频的默认推理器。关于两款 App 不花云 API 费的实现边界见免费离线语音与本地 Agent 的完整方案；具体 SDK 机型与语言资格见Google AI Edge 离线语音研究。

我们已有多模型接入与 Agent 工具，但还没有 Gemini 4 三模型自动路由实测

这里有一个很重要的“已实现”和“待升级”分界。RecalAI 并非缺少云模型接入：当前 Android 的 CloudProviders 实际支持 OpenAI、Anthropic、Gemini、Qwen、DeepSeek、Kimi、GLM、混元、Grok 和 OpenAI-compatible 接口；每个 Provider 保存独立的地址、模型 ID 和授权状态，发送私有问题与证据前需要明确的用户同意与 API Key。但仓库里的 Gemini 预设仍是 gemini-2.5-flash，不能把“已经支持 Gemini 供应商”写成“已经跑过 Hydrogen / Argon / Carbon 三模型”。

工程环节现有项目代码中的能力对 Gemini 4 的实际要求
供应商选择RecalAI 已有端侧 BYOK/多服务商配置，Android 云请求检查用户同意与凭证，iOS/macOS 有云模型选择与授权入口需要核对三款 Gemini 4 的真实 API ID、资格、工具调用和错误码，不能仅更换显示名称
本地检索iOS/macOS/Android 已有私有资料检索与引用链路；Android 的 HybridSearchEngine 和 MediaPipe/LiteRT Embedding 代码用于本地召回Gemini 只接触经用户许可的最小证据集合，不接管本地资料库索引

因此，“本地/现有 Provider 作为基本路线 → 遇到经授权且确实复杂的推理任务才评估 Gemini 4 升级”更贴近现在的产品事实。文章后面讨论的 Hydrogen/Argon/Carbon 分工是升级评估，不是已经上线的模型路由运行日志。若只需要不产生付费云 API 账单的具体做法，可转至免费方案中的实际端侧实现与本地 Agent 约束；需要了解语音链路和设备差异，则看Google AI Edge 与现有 Apple/Android 语音方案的区别。

iPhone 13 的慢，不是付费模型路由的依据

RecalAI 开发者反馈端侧语音识别基本准确、搜索可用，但 iPhone 13 响应偏慢；没有分段延迟日志能证实瓶颈属于 ASR、检索还是本地模型。模型路由只有在明确的复杂推理任务和用户授权下才值得评估，不能把“换用收费 Gemini”包装成已验证的性能修复。端侧性能定位详见免费本地 AI 方案与 iPhone 13 实际体验。

先纠正三种常见的选型误区

图示：选择应取决于具体任务、权限和验收条件，不应只按模型大小排序。

第一，Hydrogen 不等于“只适合简单任务”。 Google 的公告显示 Hydrogen 支持可配置的 Thinking Level，并报告某些综合基准上高努力配置具有很强的成绩。不同模型在不同任务分布上可能反超，不能把一个品牌里的命名顺序当成通用能力排名。对持续重复、可以自动验收的工作，快速模型的价值可能不仅是便宜，更是缩短“提出改动—运行验证—修复回归”的反馈周期。

第二，Carbon 与 Argon 的标准单价目前并不不同。 Google Gemini API 官方价格表（核对日期：2026-11-17）如下：

模型Google 的任务定位标准输入价 / 百万 Token标准输出价 / 百万 Token
Gemini 4 Hydrogen高频编码、交互和 Agent 执行$1.50$7.50
Gemini 4 Argon通用复杂工程与知识任务11 月 30 日前 2，12月1日起2，12 月 1 日起 2，12月1日起411 月 30 日前 10，12月1日起10，12 月 1 日起 10，12月1日起20
Gemini 4 Carbon复杂多步推理、长时 Agent、困难调试11 月 30 日前 2，12月1日起2，12 月 1 日起 2，12月1日起411 月 30 日前 10，12月1日起10，12 月 1 日起 10，12月1日起20

以上均为标准 API 公告价，不等于 IDE 订阅额度；输出价格包含 thinking tokens，实际还可能涉及缓存、工具调用、额外检索、服务层级和汇率/税费。Carbon 的一次任务如果消耗了更多思考与重试 Token，即使与 Argon 每个 Token 标价相同，总成本依然可能更高。Google 官方定价

关于免费层的补充：Hydrogen 与 Argon/Carbon 不同，Google 为 Hydrogen 提供有配额限制的免费 API 层。 正式生产的付费 Standard 价格如上表；Google 提示免费层内容可能用于改进其产品，因此不能用这项免费额度默认处理 RecalAI 的私人文档、Lunest 的睡眠录音等敏感数据。Argon 与 Carbon 的普通 API 目前没有免费层。免费试用适合公开或合成的工程 Fixture，但不等同于合规的长期生产免费服务。Gemini API 官方价格与免费层条款

第三，模型路由不等于把一个聊天记录原样转交另一个模型。 工程上应迁移经过验证的任务目标、已授权工具、当前检查点、可重放的观察结果、已提交副作用与尚待确认动作，而不是假设新模型能直接理解前一模型的内部推理轨迹或隐藏状态。对会发邮件、修改文件、操作账号或写入数据的 Agent，这种差异可能直接造成重复执行。

因此，真正的设计对象不是一张“模型跑分表”，而是带有权限、任务状态、费用和独立验收的执行系统。

把模型放回任务里：三类工作用三种不同的分配策略

场景一：RecalAI 的引用回跳，首先是确定性正确性问题

在 RecalAI 的个人知识库中，用户可能问“把所有提到某项数据保留规定的文件总结一下，并逐条注明出处”。任务的关键不在于回答写得多流畅，而是能否完整找到相关材料、正确区别同名文件、把每条结论锚定到真实片段，以及在文件被修改后保持引用回跳一致。

对这类工作，“Hydrogen 先读文档，Carbon 最后总结”并不天然更正确。更合理的是按照权限边界和可验证步骤拆分：

阶段哪些工作交给确定性程序候选模型职责验收依据
本地导入与解析文件类型、OCR、段落、时间戳、哈希和 FTS 索引不调用云模型原文件与 Chunk 可回溯
召回与候选排序FTS/向量检索、RRF、来源过滤、去重仅在明确需要时评估可选模型辅助Recall、引用可用性与权限边界
证据选择与总结白名单来源、证据 ID 校验、结构化输出验证本地模型为默认；用户明确授权时才可选云模型每条结论都有合法引用
失败复核断言引用 ID、文件存在、引用偏移正确对困难但获授权的推理可试 Argon/Carbon错误引用率与人工验收

本地私有数据不能成为“更强云模型”的默认输入。 RecalAI 的长期产品约束是资料默认本地，用户可自行选择第三方云端模型并在设备端配置 API Key。即使选用 Gemini，路由器也必须先检查用户对该次任务的提供商、数据范围与外传选择；拒绝的情况下仅使用本地模型或明确失败提示，不能以“提高准确率”为由上传文档。这里是产品约束及建议的决策策略，不是已经运行的 Gemini API 路由功能。

真实工程中，错误引用和隐私泄露不允许用较低平均 API 费用抵消。因此，模型判断最好发生在证据边界之后，而不是之前。

场景二：Lunest 的整夜播放恢复，大模型不是第一道处理器

Lunest 需要保证长时间音景播放、后台监测、来电中断与恢复。设想音频在第六小时被系统打断：播放器是否仍有可用缓冲、音频焦点是否已恢复、播放位置是否一致、会话是否已终止，都是应由客户端生命周期状态机和日志来回答的问题，不是应该把用户整夜声音发给 Carbon 让它猜的问题。

模型路由在这里更适合开发与测试工作流，而非睡眠监测现场推理：先用固定的非敏感故障序列描述来复现问题；对普通编译失败与局部状态修复，使用 Hydrogen 等快速执行候选；当修复涉及跨端共享会话、重复播放、音频焦点竞争和安全回滚时，才考虑使用 Argon/Carbon 对设计作第二意见，再由独立测试确认。无论谁提出补丁，最终都由 iOS/Android 的真实播放器、系统中断模拟和连续真机测试验收。

建议把修复任务定义为“完整复原一次中断且没有新增回归”，而不是“生成的代码看上去合理”。如果 Hydrogen 生成了补丁但恢复后播放进度丢失，它就是失败；如果 Carbon 给出一篇详细解释但不能通过同一组集成测试，也同样失败。模型越大不免除回归责任。

场景三：XBSTACK 双语网站更新，模型会写不等于可以发布

XBSTACK 的文章和前端改动有一套明确边界：既有 URL 不轻易迁移、中文英文不能交叉引用图片、AEO/GEO 不能变成面对用户的伪装隐藏文字、Canonical 与 hreflang 要一致，发布必须先通过构建门禁，再核验公网版本和真实搜索提交回执。

这类工作特别适合检验模型负责候选修改、工具负责独立证据的分工。一个合理的任务切分是：Hydrogen 等较快模型执行有限范围的正文检查、元数据建议或局部代码改动；Argon 复核关联影响、复杂兼容性或跨语言语义；仅在跨层设计互相冲突且证据不足时升级 Carbon；而 Astro check、双语审计、预发布门禁、构建后的 canonical/JSON-LD 检查、Git 差异与公网 HTTP 真实性，必须由确定性工具独立验证。

如果一个较快模型两次修改都通过全部门禁，未必需要昂贵模型重做；如果三次重试仍不能解释 Schema 与正文的矛盾，应停止试错、归档失败差异并升级调查，而不是无上限烧 Token。这里描述的是建议的评估策略，并非已在 XBSTACK 上完成 Gemini 4 三模型对照。

图示：本地确定性校验优先，三个案例均未完成 Gemini 4 三模型自动路由实测。

模型路由要受五个约束，而不是只看“难度”

图示：涉及外部副作用的动作不应仅凭模型判断自动执行。

一个用于真实项目的路由决策至少包含以下五维：

  1. 数据边界：资料是否含私人录音、用户文件、密钥或尚未公开的代码；是否存在用户对云服务的明确授权。未通过时直接选择本地路径或拒绝云调用。
  2. 任务可验证性：能否用固定 Fixture、单元测试、引用规则或系统日志确定成功。高可验证任务不一定需要更大的推理模型。
  3. 副作用等级：是否只是阅读/草拟，还是可能修改数据库、支付、删除文件、发布文章。副作用高时即便使用更强模型也必须预检权限、人工确认和幂等保护。
  4. 时间与资源预算：本次任务是 UI 交互秒级响应，还是允许较长时间的架构审查；是否设定 Token、重试和总费用上限。
  5. 升级触发器：只在诊断出证据不足、跨域歧义或多次可复现失败时升级到更重推理，而不是默认“所有失败先换 Carbon”。

更具体地说，合理的候选顺序是 deterministic/local → Hydrogen → Argon → Carbon → human review；这是一条待验证的政策假设，不是固定的最佳组合。某些安全敏感、高复杂度任务可以从人工/规则审查开始，某些短任务也可能直接选 Argon。应用应该记录决策理由，允许对同一固定任务集回放和比较。

“每百万 Token 更便宜”为什么不代表“每个成功任务更便宜”

图示：单次 Token 单价低，并不保证通过验收的任务总费用更低。

假设一个单轮候选调用确实消耗 100,000 输入 Token、20,000 输出 Token，只按官方标准单价、不考虑缓存和额外工具，2026 年 11 月 17 日的演算例子如下：

模型输入费用输出费用合计
Hydrogen0.10 × 1.50=1.50 = 1.50=0.150.02 × 7.50=7.50 = 7.50=0.15$0.30
Argon0.10 × 2.00=2.00 = 2.00=0.200.02 × 10.00=10.00 = 10.00=0.20$0.40
Carbon0.10 × 2.00=2.00 = 2.00=0.200.02 × 10.00=10.00 = 10.00=0.20$0.40

这只是相同 Token 假设下的价格算术，不是三款模型实际生成了相同输出长度、相同正确率或得到上述账单的证据。Carbon 与 Argon 的真正费用差异可能出现在任务使用的 thinking 和工具迭代数量。Google 还将 Carbon/Argon 标准价格在 2026 年 12 月 1 日从 2/2/2/10 调整为 4/4/4/20，不能把 11 月促销价当成永久定价。官方价格表

更适用于生产的指标是：

每个被验收的成功任务成本 = 所有执行、失败、重试、升级、验证与工具费用 ÷ 最终通过独立验收的任务数。

这一分母不能偷换成 API 返回 200 的次数。成功必须符合事先固定的验收标准。例如 30 个给定的文件引用任务，如果 25 个回答写得通顺，却只有 18 个引用正确，则合格的成功数应按照引用门禁计量，而不是把 25 当成功。数字 30/25/18 在这里仅为定义指标的假设示例，不是 XBSTACK 测试结果。

进一步需要比较 单模型 Hydrogen、单模型 Argon、单模型 Carbon、按风险升级的路由政策 四组，并让它们使用相同任务、相同输入、相同工具权限、相同超时和相同人工审核标准。按模型名比较一次最好结果，不能支持路由策略优于单模型的判断。

跨模型接力真正危险的地方：状态、权限和重复副作用

图示：无法确认外部工具是否执行成功时，应停止自动重试，避免重复副作用。

最需要防范的不是“回退模型变笨”，而是回退前一个工具动作已经真实发生，后一个模型却再次执行它。例如 Agent 已创建草稿、写入文件或发送邮件，但原模型的响应在网络超时后丢失；如果系统只把“调用失败”交给另一模型，可能在没有确认提交状态前重复产生副作用。

模型接力记录不应只是一段对话摘要，至少要有：

检查点字段目的
task_id / input_digest标识同一用户任务，避免重复接收
policy_version / consent_scope固定当时的数据权限和工具白名单
provider / model / thinking_level证明使用了哪个模型与推理等级
step_id / state / tool_result区分未执行、执行中、已提交、待人工确认
idempotency_key / external_effect_receipt在重试之前核验外部副作用是否已经生效
usage_tokens / tool_cost / retry_budget支持真实成本与熔断
acceptance_evidence / human_override区分模型自评和测试真实结果

跨模型交接时，只传递已经校验的可重放资料和必要任务状态；不依赖隐藏思考文本可在不同模型间互通。高风险工具操作必须确认提交结果，无法确认时停止并进入人工核查，不得把“请求超时”等价为“操作一定没发生”。

RecalAI 的本地用户数据尤其需要严格隔离：即使用户开启 BYOK，也不代表每次后续调用都可以无限制把整库资料传给云模型。Lunest 的睡眠原始音频与私有报告也不该仅因为开发者正在评测云端模型就成为训练/测试材料。建议使用合成、公开或经过授权脱敏的 Fixture；不要在计费实验里上传真实个人资料。

哪些证据才能支持“Hydrogen + Carbon 路由更划算”

图示：图示为可复核的实验设计，不提供尚不存在的完成率或成本结果。

Google 官方称其 Orchestrator 在某些软件工程基准中相较 Carbon 单独运行具有更低配额消耗和更快任务完成速度，这可以形成测试假设，但不能直接当成 Lunest、RecalAI 或 XBSTACK 的本地收益。Antigravity 产品内的 Orchestrator 也不能自动等同于开发者在 Gemini API 上已经拥有可直接复制的路由服务。Google 模型公告

对本站，建议使用不泄露私有数据的三类固定任务作为评估基准：

  • RecalAI 引用校验：合成文件集合含同名文件、版本冲突、否定词和精确锚点；比较正确引用、漏召回、越权引用和人工复核成本，而不只比较回答流畅度。
  • Lunest 中断恢复：脱敏状态序列涵盖来电、蓝牙切换、后台播放、重复开始、缓存损坏；以集成回归和真实设备播放是否稳定为依据。
  • XBSTACK 双语发布质量：固定一组含 Canonical/Hreflang、GEO/Schema 与旧 URL 保护的仓库变更；以测试、双语门禁和公网核对为验收，不拿模型说“成功”当证明。

每组记录平均与尾部延迟、失败/重试、外部副作用、人工介入、输入/思考/输出 Token、实际 API 账单和成功任务成本。项目未执行这套 Gemini 三模型 A/B 前，不提供虚构的成功率、延迟、折省比例或“实测推荐排名”。

结论：路由优化的第一步可能是减少模型调用

在可信的 Agent 工作流中，最值得投资的不是“让所有步骤都由三种模型接力”，而是让确定性程序处理确定性问题、让本地数据始终拥有明确的隐私边界、让有风险的工具动作可核实且可停止。Hydrogen 可成为可验证高频任务的候选；Argon 可以承担较多通用审查；Carbon 可以留给长时复杂冲突。但这只是待固定任务数据验证的工程假设，不是厂家型号越大越安全的承诺。

从 RecalAI 到 Lunest，再到网站发布：能够证明完成、知道失败、保留来源、控制费用且尊重用户数据，比一个漂亮的模型排行榜更接近值得上线的系统。

这些工程案例对应哪两款产品

RecalAI 与 Lunest 均处于开发阶段，当前尚未在 App Store / Google Play 正式开放公开下载。你可以查看 RecalAI 的站内产品页（目前以 Recalia 命名）及 Lunest 产品说明了解定位和开发状态。本文的云模型路由是研究方案，并非两个 App 已部署 Gemini 4 三模型自动路由的产品公告。

如果不想付 API 费用，还有怎样的工程路线？

收费模型路由并非任何 App 的必经路线。对于需要默认本地运行的 RecalAI、Lunest，免费离线语音与本地 AI Agent 的独立研究比较了 Apple Speech、Android ML Kit、MediaPipe/LiteRT、llama.cpp 与有限免费云 API：它解决的是“哪些工作能不产生云 API 账单，并且仍然守住设备内存和隐私”，不是重新比较三款 Gemini 的跑分。有关语音专门的 SDK/机型资格和失败回退，再看Google AI Edge 离线语音与 TTS 的工程边界。
