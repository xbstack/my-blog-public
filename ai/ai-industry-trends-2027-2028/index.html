XBSTACK 产业研究｜资料截止：2026 年 10 月 26 日。 本文以 Google、Apple、OpenAI、Stanford HAI、Gartner、IDC 等一手公开资料为证据。将已经发生的产品发布、机构预测和作者对 2027—2028 年的判断明确区分；不假装做过企业访谈，也不将 RecalAI 的 Mac 研究代理结果称为端侧手机实测。

2027 AI 产业趋势的核心判断不是“云端取代端侧”或“小模型取代大模型”。 未来两年的更可能格局是：云端承接长周期、高复杂度、跨应用执行；端侧承接实时交互、隐私敏感处理、离线检索与部分推理；大模型负责复杂决策，小模型负责高频低成本子任务；多模态逐渐成为应用默认能力，竞争从模型能力延伸到基础设施、入口、数据、执行环境与商业闭环。但所有这条演进链都必须建立在隐私保护、最小权限、可撤销的数据使用权和可核验的安全执行之上；安全可控将从差异化卖点上升为能否被用户及企业信任的基本条件。

如果希望从产业判断继续深入到可执行的技术方案，可先从 XBSTACK 的 AI 工程专题 进入 Agent、端侧模型与安全治理分支。

这一判断为什么值得重视？因为它把“AI 又发布了新模型”的新闻，转化成了研发负责人真正要回答的问题：下一笔预算应该投在哪里、任务在哪一端执行、使用多大的模型，以及怎样判断是否产生了实际价值。

二、云端化：从“调用云模型”升级为“让 Agent 在云端持续工作”

以前的云端 AI 主要提供模型推理：应用发送问题、服务返回答案，用户关闭客户端后交互通常结束。2026 年更重要的变化，是云端开始承担任务状态、文件环境、工具执行、沙箱、子 Agent 和跨设备续接。

Google Cloud 于 10 月 8 日介绍了一个云端持续运行的 Gemini 工作 Agent：可在多个应用和设备间保留记忆、上下文与任务进度，支持长达数小时或数天的流程和子 Agent 编排。10 月 22 日，Google 又宣布 Agent Compute Engine，目标提供硬件隔离的云端沙箱与统一治理，但官方明确该计算服务将在随后几个月进入预览，不能当作当天已全面商用。OpenAI 2026 年 Agents SDK 更新同样强化了沙箱中访问文件、运行命令与长任务执行的能力。来源：Google Gemini at Work、Google Agent Compute Engine、OpenAI Agents SDK。

趋势判断： 2027—2028 年，竞争对象可能从“谁的 API 推理分数高”扩大到“谁提供完整的可信 Agent 运行环境”。长任务状态、浏览器/文件操作、企业身份、网络出口、工具权限和审计是平台壁垒的一部分。

实际部署时，云端长任务还需要区分共享与独占工作空间、网络出口和数据留存，可结合 AI Agent Sandbox：Hosted 与 Self-hosted 的边界 进一步选型。

但“云端化”不等于数据没有边界。持续运行需要长期保存或引用上下文，跨设备共享涉及授权、费用、地域、私密信息与可删除性。一个标称云端的产品也可能采用本地文件索引或客户托管环境。云端 Agent、云模型 API、云端存储和私有云部署是四个不同层次。

三、端侧 AI：为什么云端 Agent 越强，设备端仍值得投入？

在云端长任务之外，端侧 AI 有四类持久需求：低延迟交互、网络不稳定场景、私密资料处理，以及与摄像头、麦克风、屏幕和本地文件的自然结合。其价值不是在手机上重演所有服务器功能。

Apple 在 2026 年公布第三代 Apple Foundation Models，明确将设备端模型与 Private Cloud Compute 上的服务端模型结合；其中设备端包含约 3B 量级的 AFM 3 Core 等模型。Google AI Edge 的 LiteRT-LM 则描述了 Android、iOS、桌面与 Web 的设备推理路径，支持 GPU/NPU、多模态与函数调用，官方演示可以离线运行。来源：Apple Foundation Models、Google LiteRT-LM。

端侧体验不是只看 Tokens/s。开发者至少应报告模型文件大小、首次加载时长、峰值常驻内存、P50/P95、后台恢复、耗电、发热、冷启动、离线准确率与不同设备分层。Google 的公开硬件性能表是厂商在指定设备上的基准，不能照搬成 RecalAI 在 iPhone 13 上的实测成绩。

趋势判断： 端侧 AI 更可能首先在“搜索、整理、分类、转写、检索、短文本理解、个性化提示”中形成可用基础能力；耗时的深入推理、超大上下文、多工具长任务则保留可选择的云端升级路径。

端侧不是自动安全的同义词：本地应用依旧要审查文档权限、沙箱边界、加密密钥、备份同步与模型日志；云端也不能仅凭“零保留”营销语保证用户数据主权。关键误区是把**本地优先（local-first）**等同于“永远不上云”。用户通过 BYOK 云模型提出问题时，可能仍会外传选定的上下文；隐私声明要按动作逐项说明，而不是靠一个产品标签解决。

本地部署的模型体积和实际内存不是同一个指标。有关 GGUF、MLX、量化、KV Cache 等选型边界，可参考 LFM2.5-24B-A2B 在 Mac 上的内存与格式选择；该文是部署研究，不冒充所有设备的实测。

四、小模型不是大模型的廉价替身，而是另一种工程分工

“小模型”至少有三类，经常被行业报道混淆：

  1. 可在设备端运行的小模型（On-device SLM）：关注低 RAM、量化、响应延迟、离线能力。例如 Gemma 4 E2B/E4B，具体可运行设备仍取决于量化和内存预算。
  2. 云端高吞吐小模型：如 OpenAI 2026 年 3 月的 GPT-5.4 mini/nano、Anthropic 2026 年 10 月的 Claude Haiku 5.5。它们适合分类、提取、路由、子任务，但名字叫 mini 并不表示用户能把它下载到手机本地运行。
  3. 专用小模型：Embedding、Rerank、OCR、语音、函数调用和领域分类，未必承担自然语言长文生成。2026 年 Google 的 EmbeddingGemma 2 约 7.4 亿参数，是把文本、图像、音频及视频映射到统一空间的多模态检索模型，而不是通用聊天大模型。

来源：Gemma 4、OpenAI mini/nano、Anthropic model releases、EmbeddingGemma 2。

核心变化： 2027 年的“模型选型”可能越来越像成本敏感的计算调度——先以简单规则或本地模型处理确定性任务，再由必要时可用的高性能云模型完成复杂推理。量化、蒸馏、缓存、投机解码和批处理都可能影响成本；但每种加速都有可能牺牲精度或引入集成复杂度。

反证： 如果新一代大模型在所有相关任务上同时更准确、更快、更便宜，单独路由的价值就可能下降；如果小模型错误率导致严重的人工返工，它也未必省钱。所以不要用参数量决定路线，而要比较固定任务集下的完整成功成本。

六、多模态 AI：从“看懂图片”走向能搜索和操作真实内容

文本检索难以覆盖用户真正的资料：手机照片、票据、图表、语音、录屏、视频和软件界面都可能包含重要事实。多模态趋势更值得研究的不是生成几张好看的图，而是信息从感知、检索到动作的端到端闭环。

Google 于 10 月 6 日发布 EmbeddingGemma 2，约 740M 参数，将文本、图像、音频与视频统一到检索表示空间；官方披露的相关模型尺寸依配置不同而变化。Gemini 4 Argon 则代表云端高强度推理和长上下文路线，10 月 13 日正式面向开发者/企业推出；这与端侧 Embedding 是用途不同的两种能力。来源：EmbeddingGemma 2、Gemini 4 Argon。

2027—2028 判断： AI 原生应用的关键竞争点可能逐步变为“能否正确检索视频某一帧、PDF 表格某个单元格、录音中的具体证据，再给出可追溯答案”。跨模态召回会增长，但视频切片、OCR、时间轴索引、存储与隐私也增加成本。

如果重点是检索质量而非生成能力，本站的 EmbeddingGemma 2 Mac 本地检索实测 记录了指定 PDF/Word 数据集、FTS5、向量与 RRF 的对照，同时说明它不代表手机或生产环境的效果。

需要严格区分原生多模态模型、多模态 Embedding、OCR + 文本 RAG 流水线：它们都能处理非文本资料，却不代表相同的推理能力，也不能凭一个厂商 Benchmark 宣称现场效果已经达到。

七、Agent 与 Personal AI：真正变化的是入口、记忆和执行责任

云端持续 Agent 与端侧私人助手正在形成不同但互相依赖的产品路线。企业 Agent 更关注工具、流程、可恢复状态和授权；Personal AI 则特别依赖属于用户的上下文、证据、长期记忆、可迁移/可删除性。

XBSTACK 的 RecalAI 混合检索研究 记录了源码中的精确、严格/宽松词法、向量和加权融合等候选获取与引用校验设计，但它不是 iPhone 性能测评。在 2026 年 10 月 26 日独立准备的研究材料里，10 份公开 PDF、20 条文档级问题的 Mac 词法/非神经代理检索出现过首位错排。这只说明**“召回到证据”和“把正确证据排第一”可能不同**；不能用它断言某款设备端模型的真实质量。

对长期记忆，系统应能解释：这段记忆来自哪里、是否过期、谁可以访问、删除后索引和备份是否留下副本。既有 Personal AI Agent 架构 与 Agent Security 专题 分别详述应用结构与安全；本文只判断其长期产业位置，不重复整套安全教程。

趋势判断： 过去 AI 助手主要竞争模型回答能力，之后可能更多竞争用户数据的可控上下文、跨设备连续体验、长期任务的可信托管和实际完成结果。这既是机会，也是平台生态和隐私政策带来的限制。

Personal AI 概念流程：来源可追溯、记忆与权限由用户管理。画面中的隐私说明属于产品设计目标，不是对现有产品绝对安全的承诺。

八、隐私与安全可控：从产品设置走向 AI 基础架构和商业准入

安全不是“Agent 能调用工具”之后才考虑的补丁。2026 年 5 月，**NIST 关于 AI Agent 安全的 RFI 汇总（AI 800-5）**指出，回应者普遍将 Agent 带来的新威胁视为部署障碍，并认为传统网络安全原则仍适用、但需要为具备自主工具调用能力的系统调整。2025 年底的 OWASP Agentic Applications Top 10 也将 Agent 专属风险整理为面向工程团队的公开清单，包括权限滥用、工具误用、记忆污染和间接提示词注入。它们提供的是风险框架，不是“2027 年事故发生率必然增加”之类的统计预测。来源：NIST Agent 安全回应分析、OWASP Agentic Top 10。

与此同时，隐私技术路线本身已经出现可验证的新信号。Apple 的 Private Cloud Compute 安全指南强调请求相关数据的无状态处理，并公开可供独立研究的 可验证透明机制；Google 2026 年 10 月 7 日发布面向 Android 个性化设备 AI 的 AISeal 安全隔离架构，结合受保护虚拟机隔离敏感 AI 上下文。这些是各厂商在限定部署边界内的设计与声明，不能概括为所有 AI 云服务均不存储数据，或所有 Android 手机、第三方 App 都已经具备相同硬件隔离能力。

六个可审计的“用户真正可控”能力

控制层对用户真正意味着什么产品应提供的行为应验证的证据
数据驻留与用途知道资料在哪、为什么被处理、是否上云按任务选择本地/云端，明确范围与保留期限，不上传未选择的私有上下文端点/请求审计、出站数据最小化
身份与最小权限AI 不能因为会调用工具就自动拥有用户全部权限每工具、每数据源限定只读/写入 Scope，有期限、能撤销越权负面用例、权限撤销后失败
高风险动作审批发消息、转账、删除、批量变更前可预览和中止明确操作预览、二次确认、限额、幂等与回滚策略未确认不执行、重复调用不重复副作用

审计与责任知道 AI 做了什么、谁批准的、失败怎样恢复可读执行记录、最少敏感日志、撤销和停止机制任务成功率、授权记录和安全事件响应

这不是要求所有个人产品照搬企业级合规系统：操作风险越低，界面越应简洁；但有外部副作用的动作必须比单纯阅读、搜索和生成文本受到更严格控制。对于涉及医疗、财务、个人身份或企业凭据的任务，授权和最小化外传尤其重要。联合网络安全机构发布的 CISA《Careful Adoption of Agentic AI Services》明确主张限制 Agent 自治范围、分层防护、身份管理、监控和持续评估。

为什么它将成为一项真正的产业趋势？

第一，入口变化提高信任成本。 AI 从“建议你怎么做”进入“代你访问和修改系统”，风险从内容错误升级为真实副作用。第二，端侧 Personal AI 沉淀更多高敏上下文。 邮件、日历、相册、文件与长期记忆一旦集中，单一越权比普通聊天泄露更严重。第三，企业采购开始把可审计权限和数据流列为准入门槛。 这是一项由安全规范和产品工程共同支持的趋势判断，尚不能据此给出全球采购比例或统一利润率预测。

到 2027—2028 年，值得观察的不是谁喊“最安全”，而是安全是否被可复现地证明：撤销工具授权后还会不会调用？删除记忆后会不会被检索回来？离线模式下有没有暗中联网？恶意网页或 PDF 能否指示 Agent 发送私有数据？用户能否获取审计记录并真正停止运行中的任务？如果这些指标得不到改善，“安全可控成为主流价值”的判断便应被修正。

隐私治理还应区分模型厂商的数据保留配置与第三方工具的数据生命周期，例如 OpenAI Zero Data Retention、Responses API 与 MCP 数据边界 对远程 MCP 和缓存等问题进行了单独梳理。

网站已有 Agent Security Hub 和 Agent Security Auditor 对风险与静态审计作深入拆解；本篇关注它们与端云计算、用户信任、企业采购和长期商业化的产业关系，避免重复一整篇安全教程。

九、算力与基础设施：从训练 GPU 扩大到推理、电力、内存和网络

云端 Agent 持续执行、多模态输入、长上下文、子模型分工都可能增加总请求量。即便单次推理越来越便宜，长期工作流更复杂，总算力需求也不必同步下降。

IDC 于 10 月 22 日判断，AI 的短期增长瓶颈越来越多地来自电力、内存、封装与数据中心建设，供给限制可能延续到 2027—2028 年。这是研究机构的产业判断，不是每一个区域和芯片型号都短缺的证明。Gartner 于 9 月更新 2026 年全球 AI 支出预测，同比增长率约 49.5%；支出增长不是盈利增长，也不等于所有上市公司都能持续赚取超额回报。来源：IDC、Gartner 支出预测。

三层不能混为一谈的产业收益

  • 上游容量：GPU/ASIC、HBM、先进封装、服务器、供电和液冷；最敏感的是交付能力、资本开支及供需周期。
  • 中游服务：云推理、托管 Agent、数据库、推理优化、安全沙箱；最敏感的是设备利用率、单位计算毛利、客户黏性和采购成本。
  • 下游应用：Personal AI、行业软件、开发者工具和内容工作流；最敏感的是任务成功率、留存、毛利和真实付费意愿。

宏观 AI 投资规模不能直接推导股票涨幅。研究企业盈利时，须分清主营收入、毛利、经营利润、扣非净利润、投资/公允价值损益、资本开支与经营现金流，避免将非主营收益误称为 AI 业务利润。

十、开源与闭源竞争：不再只是“哪个模型榜一”

Stanford HAI《AI Index 2026》显示，头部模型能力持续快速提高，同时闭源与开放模型在一些测评中仍有差距，不存在“开源模型已全面追平”的一刀切结论。Google 的 Gemma 4、行业其他开放权重路线和端侧推理框架使自主部署、量化、数据控制成为可选项；前沿闭源模型在复杂推理、工具集成和云资源方面仍可能有优势。来源：Stanford 技术性能、Gemma 4。

趋势判断： 2027—2028 年的商业竞争可能沿三条路线分化：闭源前沿能力服务、开放/可托管模型能力、适合固定业务或端侧设备的高效专用模型。对于应用企业，重要的是可替换性、数据边界、推理成本、模型维护周期与领域任务正确率，而不是对某一家模型的长期忠诚。

不能忽视生态锁定风险：API 或 SDK 升级、价格变动、配额、地区限制、端侧芯片架构和模型许可证都有可能使一次模型切换变成昂贵的迁移工程。

十一、商业化：谁拥有入口、流程、用户数据与付费关系？

AI 市场规模扩大，并不保证每一款 AI 应用都会赚钱。随着模型变成可通过云 API 或设备 SDK 获取的基础能力，竞争优势可能沿着四种资源迁移：

  1. 入口：操作系统、办公套件、浏览器、搜索、开发工具；能直接触达用户和当前任务，但也可能受平台反垄断、隐私和互操作约束。
  2. 上下文：用户授权的文件、工作历史、企业流程和长期记忆；必须解决访问权限与可撤销性。
  3. 执行：可靠的沙箱、状态管理、审批、任务恢复和实际结果；行业软件与 Agent 平台在此竞争。
  4. 客户信任与服务：专业场景精度、透明定价、售后、长期维护；个人开发者要找到平台不会轻易提供、但用户会反复遇到的真实问题。

评估 ROI 时，不要只看“每百万 Token 单价”。应按每个经验证成功的任务核算模型推理、解析检索、工具运行、重试、人工纠错、审批和运维总成本。

成本示意：Token 单价下降不意味着完整任务成本一定下降；趋势线不代表真实采样数据，成本比较仍应采用相同任务集。

成本治理中，减少无效检索、工具列表和上下文注入同样重要，可参照 Context Engineering：Retrieval、Tool Search 与 Memory 的成本边界；它补充工程手段，不替代本篇的产业情景分析。

举一个数学假设，不是市场实测：原来每个子动作 0.05 美元，需要 10 次动作，单项任务推理成本为 0.50 美元；后来每次动作只要 0.01 美元，但复杂任务需要 100 次动作，单项就变成 1 美元。单次动作便宜了 80%，完整任务仍贵一倍。不同机构对“单动作成本”和“整个 Agent 工作流成本”的预测可能同时成立，具体结果必须由同一任务集的账单验证。

十二、具身智能和物理 AI：增长机会很大，但不能套用软件发布周期

大模型的视觉、推理和动作规划改进，为机器人、自动驾驶和工业智能提供了技术条件。但实体系统要付出的代价还包括传感器、执行器、长尾场景数据、安全验证、维修与物理责任。

Stanford 2026 AI Index 的技术章节显示，机器人在真实家庭任务上的成功率仍远低于受控模拟环境。自动驾驶的一些指定区域已形成规模化服务，这与通用人形家务机器人形成鲜明对比。**这说明机器人商业化更可能先发生在高重复、较受控、可测量收益的场景，而非所有家庭任务同时爆发。**来源：Stanford 技术性能。

这是中长期观察方向，但不宜把未来 24 个月的工业、配送、车载、家用机器人混成同一个“马上普及”时间表。

十三、2027—2028 三种情景与五项反证指标

十四、给企业与独立开发者的 90 天取舍建议

第一个月：统一任务与证据。 为实际用户的十类重复任务建立样本，区分精确检索、跨文件总结、视觉问答、工具写入、长任务；保存每类正确答案、来源、可接受时延和隐私边界。并行摸清云端推理费、设备 RAM 和外部工具权限，不先构造“大一统超级 Agent”。

第二个月：设计端云分层。 在可用设备上先测 FTS、Embedding/OCR、模型加载和基础交互；将需要深度推理或持续执行的任务隔离进明确授权的云端流程。对每种功能至少保留一个小模型/大模型基线，避免被某个供应商 API 绑住。

第三个月：决定是否扩大。 审核引用是否支持答案、工具执行是否有实际成功事件、用户是否回访、端侧是否触发内存告警、云端是否因重试超额。失败案例公开记录，做到能切换或关闭单项能力。对于 RecalAI，应先保证资料导入、精确检索、引用和可撤销数据边界，再考虑宣传更大模型。

十五、从趋势到实际选型：八个高频问题

云端 Agent 会替代端侧 AI 吗？ 不会简单取代。持续的跨应用工作更适合有状态管理和沙箱的云端环境；离线检索、即时交互和私有资料处理通常更适合设备端。实际选择还要看设备能力、用户授权和总体任务成本。

端侧小模型与云端 mini 模型有什么不同？ 端侧 SLM 关注本地权重、内存、量化和离线能力；云端 mini/nano 主要是托管服务的性能与价格分层。模型都叫“小”并不意味着具有相同的部署和数据保护边界。

小模型会取代大模型吗？ 不宜做绝对判断。高频分类、检索、提取可能由专用或小模型更经济地承担，而复杂推理可能仍需前沿模型。应在同一测试集上核算成功率、延迟和单位成功任务成本。

为什么 Token 降价后 AI Agent 可能仍更贵？ 工作流可能调用更多模型、工具和子 Agent，并增加重试、审批、存储与错误恢复。比较成本时必须固定任务与验收标准，而不是只比较单次模型调用的价格。

隐私优先是否意味着数据绝对不能上云？ 不意味着。关键是让用户明确知道哪些数据、为了哪个任务、传给谁、保留多久，并能控制权限。设备端、私有云、保密计算和第三方 API 的风险边界并不相同。

AI Agent 怎样做到安全可控？ 对每个工具和数据源采用最小权限，对删除、发送、批量变更等操作增加明确审批，支持撤销、停止和审计，并用恶意网页、PDF、邮件等负面测试检验是否会越权。

Personal AI 能否保证删除记忆后毫无残留？ 未经过端到端测试时不能保证。需要说明原始资料、索引、缓存、同步副本、备份和日志的具体删除范围及生效时间；安全承诺应可审计而不是绝对化。

企业和独立开发者如何验证 2027—2028 趋势判断？ 持续检查云端任务完成与恢复、端侧 RAM/P95/能耗、权限撤销负面测试、每项成功任务成本、付费留存和基础设施利用率。机器人还需另测现实任务完成、安全及维修成本。

研究结论

未来两年的 AI 竞争，不是简单由云端或本地、巨型或小型模型中的一方获胜。云端负责“能持续做复杂事情”，端侧负责“随时可靠处理身边的信息”，大小模型共同优化任务成本，多模态扩大信息入口，隐私保护、安全可控与用户数据主权决定能否被信任，基础设施与商业模式决定价值能否兑现。

云端 Agent、端侧 AI、小模型、多模态、算力供给与 Personal AI 因此不应被拆成互不关联的热点新闻。它们共同指向一个长期问题：AI 计算会被如何分配到不同设备、模型与任务，用户最终愿意为什么结果付费？
